# 02 — Архитектура

## Из чего состоит система

Четыре части, три из них — чужие сервисы (мы их только настраиваем):

1. **Фронтенд (наш сайт)** — страница с большой кнопкой и видео. Next.js + React,
   отдаётся по HTTPS.
2. **Сервер токенов (наш, маленький)** — один серверный эндпоинт `/api/token`.
   Выдаёт временный пропуск (JWT) в видео-комнату. Живёт как serverless-функция
   на том же Vercel, отдельный сервер не нужен.
3. **LiveKit Cloud (чужой)** — медиасервер, который реально передаёт аудио/видео
   между участниками. Мы его не пишем, только подключаемся по ключам.
4. **(Позже) Слой уведомлений** — чтобы второй человек узнал о звонке. См.
   [06-notifications-and-ringing.md](06-notifications-and-ringing.md).

```
┌─────────────┐     1. "дай пропуск"      ┌──────────────────┐
│             │ ────────────────────────► │  Наш сервер      │
│  Браузер    │                           │  токенов         │
│  родителя   │ ◄──────────────────────── │  /api/token      │
│  (наш сайт) │     2. JWT-токен          │  (Vercel func)   │
│             │                           └──────────────────┘
│             │                                    │ ключ + секрет
│             │     3. подключение по токену       ▼
│             │ ◄═══════════════════════► ┌──────────────────┐
└─────────────┘       аудио/видео         │  LiveKit Cloud   │
       ▲                                   │  (медиасервер)   │
       │            аудио/видео            └──────────────────┘
       ▼                                            ▲
┌─────────────┐                                     │
│  Браузер    │ ◄═══════════════════════════════════┘
│  мой        │       3. подключение по токену
└─────────────┘
```

## Как проходит звонок (happy path)

1. Родитель открывает сайт (иконка PWA на телефоне).
2. Видит большую кнопку **«Позвонить»**. Нажимает.
3. Браузер запрашивает у нашего `/api/token` пропуск в комнату `family`
   с именем участника (например, `mama`).
4. Сервер токенов проверяет, что устройство «своё» (одноразовый семейный код,
   см. ниже), и возвращает подписанный JWT.
5. Браузер с этим токеном подключается к LiveKit, включает камеру и микрофон.
6. Когда второй человек делает то же самое — оба оказываются в комнате `family`
   и видят/слышат друг друга. Медиапоток идёт через LiveKit.

## Где живёт что (карта развёртывания)

| Компонент | Где работает | Кто платит | Секреты |
|---|---|---|---|
| Фронтенд | Vercel (CDN) | бесплатно | нет |
| `/api/token` | Vercel (serverless) | бесплатно | `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `FAMILY_CODE` |
| Медиа | LiveKit Cloud | бесплатно | хранятся на стороне LiveKit |

Важно: **API-ключ и секрет LiveKit никогда не попадают в браузер**. Они только на
сервере токенов (переменные окружения Vercel). Браузер получает лишь
короткоживущий JWT на конкретную комнату.

## Модель комнат и идентичности

- **Одна постоянная комната**: `family` (имя задаём в коде/конфиге).
- **Идентичность** участника — простое имя (`mama`, `papa`, `artem`), оно
  выбирается/зашивается при настройке устройства, не требует логина.
- Поскольку звонки 1-на-1, в комнате одновременно ожидаются двое. Если зайдёт
  третий — можно либо разрешить (LiveKit потянет), либо показать «линия занята».
  На старте — не усложняем, просто пускаем.

## Безопасность при «входе одной кнопкой»

Без логина нужно как-то не пускать посторонних. Решение —
**одноразовая привязка устройства**:

1. При первой настройке устройства (это делаю я для родителя) на странице
   `/setup?code=СЕМЕЙНЫЙ_КОД` код сохраняется в `localStorage` браузера.
2. Дальше при нажатии «Позвонить» фронтенд шлёт этот код в `/api/token`.
3. Сервер сверяет код с `FAMILY_CODE` и только тогда выдаёт токен.
4. Для родителя это незаметно: код введён один раз мной, дальше — только кнопка.

Это не банковская безопасность, но полностью достаточно, чтобы случайный человек
со ссылкой не попал в семейный звонок. Подробнее и варианты строже —
в [07-livekit-setup.md](07-livekit-setup.md).

## Ключевая нерешённая проблема: как «позвонить»

LiveKit соединяет тех, кто **уже зашёл** в комнату. Он не «звонит» человеку,
который сайт сейчас не открыл. Значит, чтобы второй узнал о звонке, нужен
отдельный механизм оповещения. Это самостоятельная и важная тема —
вынесена в [06-notifications-and-ringing.md](06-notifications-and-ringing.md).

На MVP (Фаза 1) обходимся договорённостью голосом/в мессенджере: «я зашёл,
заходи». Полноценный «звонок» добавляем в Фазе 3.

## Требования среды

- **HTTPS обязателен.** Браузер не даст доступ к камере/микрофону по http
  (кроме `localhost`). Vercel выдаёт HTTPS автоматически — проблема снимается.
- **Современный браузер.** WebRTC работает в Chrome, Safari, Firefox, Edge
  актуальных версий — на всех устройствах родителей это уже есть.
- **iOS-нюанс:** Safari требует, чтобы доступ к камере запрашивался в ответ на
  жест пользователя (нажатие кнопки) — у нас так и есть, проблем не будет.
