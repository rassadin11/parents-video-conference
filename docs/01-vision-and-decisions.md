# 01 — Видение и зафиксированные решения

## Зачем этот проект

Удобный способ созваниваться по видео внутри семьи (я + родители) без сложных
приложений, регистраций и настроек. Существующие мессенджеры (WhatsApp, Telegram,
Zoom) работают, но:

- требуют установки и обновления приложений;
- родителям бывает сложно найти нужную кнопку среди десятков чатов и меню;
- иногда нужны аккаунты, подтверждения, «куда нажимать».

Наш сайт — это **отдельный «видеотелефон»** с одной задачей: соединить двух людей.
Открыл → одна кнопка → говоришь.

## Для кого

| Пользователь | Технический уровень | Что для него важно |
|---|---|---|
| Я (владелец) | Высокий (frontend-разработчик) | Контроль, простота поддержки, $0–минимум затрат |
| Родители | Начальный | Крупные кнопки, ноль шагов, ничего не сломать |

Главный «заказчик» удобства — **родители**. Все спорные решения трактуем в их пользу.

## Зафиксированные решения

Эти решения приняты на старте и определяют всю архитектуру. Менять их —
дорого, поэтому фиксируем явно.

### Р1. Видео через готовый облачный сервис (LiveKit Cloud)
**Почему:** надёжность «из коробки», работа на любых устройствах и сетях,
минимум собственного бэкенда. Свой WebRTC с нуля — это недели работы и борьба
с NAT/TURN; для семьи это неоправданно.
**Следствие:** нужен аккаунт LiveKit и небольшой серверный эндпоинт для выдачи
токенов доступа. См. [07-livekit-setup.md](07-livekit-setup.md).
**Альтернативы рассмотрены:** Daily.co (тоже отличный, чуть проще API),
self-hosted Jitsi (бесплатно, но нужен и обслуживается свой сервер). См.
[03-tech-stack.md](03-tech-stack.md).

### Р2. Только звонки 1-на-1
**Почему:** проще архитектурно и в UX. Семья небольшая, групповые звонки пока
не нужны.
**Следствие:** одна фиксированная «семейная комната», в которой одновременно
двое. Если позже понадобится группа — LiveKit это умеет, переход не ломает
основу.

### Р3. Вход — одна большая кнопка, без логинов
**Почему:** регистрация/пароли — главный барьер для родителей.
**Следствие:** доступ ограничиваем не логином, а **одноразовой привязкой
устройства** (семейный код вводится один раз при настройке, дальше — только
кнопка). Подробности безопасности — в [07-livekit-setup.md](07-livekit-setup.md).

### Р4. Адаптивный веб (телефон + компьютер + планшет), устанавливаемый как PWA
**Почему:** родители пользуются разными устройствами; нативные приложения под
iOS/Android — это лишняя сложность и публикация в сторах.
**Следствие:** сайт делаем адаптивным с крупными элементами и оформляем как
**PWA** — чтобы на телефоне появилась иконка «как приложение». См.
[08-deployment.md](08-deployment.md).

### Р5. Стоимость старта — $0
**Почему:** для семейного проекта платить не хочется.
**Следствие:** бесплатные тарифы LiveKit Cloud + Vercel. Их с запасом хватает
на семейный трафик. См. оценку в [03-tech-stack.md](03-tech-stack.md).

## Что НЕ делаем (явно вне рамок)

Чтобы не раздувать проект, на старте сознательно отказываемся от:

- групповых звонков (3+);
- записи разговоров;
- чата/сообщений/истории;
- демонстрации экрана;
- множества «комнат» и управления контактами;
- полноценной системы аккаунтов.

Любое из этого можно добавить позже, если реально понадобится. Список «потом» —
в [04-roadmap.md](04-roadmap.md), раздел «Идеи на будущее».

## Критерий успеха

> Мама/папа в одиночку, без моей помощи и без звонка-подсказки, открывают
> сайт с иконки на телефоне и за < 30 секунд видят и слышат меня.

Если это работает стабильно — проект удался.
